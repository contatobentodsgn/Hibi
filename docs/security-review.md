# Security review: extracted-code study replica

**Review date:** 2026-09-06  
**Scope:** The current `/Volumes/SSD/app/replica` source and included companion assets. This is a source-based review of the study replica, not a claim about the security of the original Hey Taby product or any unavailable upstream services.

## Executive summary

The current implementation is intentionally local-first. In the Electron desktop shell, the renderer runs with `contextIsolation: true` and `nodeIntegration: false`; the preload exposes a small, named API. The browser build has no preload bridge. Persistence is in browser `localStorage`, and the local assistant states that it makes no network calls. The repository also explicitly quarantines extracted Rive resources, debug audio, native helpers, and compiled runtime bundles.

The largest release risks are therefore governance and future drift rather than an active remote service: extracted or proprietary material could be redistributed without permission, a future build could accidentally execute quarantined code, localhost development configuration could be mistaken for a production AI endpoint, or credentials could be introduced into source, logs, support bundles, or packaged artifacts. The controls below should remain release gates.

## Findings and controls

| Area | Risk | Current control / evidence | Residual risk and required control |
| --- | --- | --- | --- |
| Extracted compiled code | High: a copied JavaScript bundle or runtime may contain hidden network, persistence, telemetry, or code-loading behavior; executing it would also make provenance and review difficult. | The asset policy says compiled application bundles and proprietary runtime code are not loaded, and the replica uses its own adapters ([asset policy](../public/companion-assets/README.md#quarantine-boundary)). The runtime asset registry contains only typed browser-served image/video references ([companion-assets.ts](../src/assets/companion-assets.ts#L1-L42)). | Keep extracted bundles outside shipped runtime paths. Review packaged contents and dependency manifests before every release; reject dynamic execution (`eval`, untrusted script injection, runtime `require`/module loading) and record provenance for any retained reference artifact. |
| Native binaries / helpers | High: a native helper can access files, processes, devices, and credentials outside the renderer sandbox. | Native helper binaries are explicitly excluded from the companion asset directory and are not automatically loaded ([asset policy](../public/companion-assets/README.md#quarantine-boundary)). Electron disables renderer Node integration and uses context isolation ([main.cjs](../electron/main.cjs#L9-L16)). | Do not ship or invoke extracted `.app`, executable, `.dylib`, `.node`, or helper artifacts unless separately reviewed, signed, permissioned, and justified. Verify the final installer/archive has no unexpected native payloads. |
| Rive / WASM / audio | Medium: `.riv`/WASM content may embed executable behavior through a runtime, and debug audio may disclose test data or create unwanted media/device assumptions. | The repository includes `rive/talk/taby-talk.riv`, `rive.wasm`, `rive_fallback.wasm`, and `debug-voice.wav`, but the policy marks these reference-only and says they are not loaded. The asset registry test asserts that `/rive/talk/` is excluded ([asset test](../src/assets/__tests__/companion-assets.test.ts#L1-L12)); the gallery lists these patterns as excluded ([CompanionAssetGallery.tsx](../src/ui/CompanionAssetGallery.tsx#L17-L25)). | Preserve the quarantine in packaging and CI. If WASM/Rive is ever enabled, pin and review the runtime, validate origins and MIME/content types, avoid untrusted animation inputs, and remove debug recordings before distribution. |
| Localhost AI endpoints | Medium: a localhost URL can still reach a local service, expose workspace data, or be redirected/proxied; an environment override can make a development path point elsewhere. | The only localhost URL in current runtime code is the Electron development URL, selected only when not packaged and when `HIBI_PRODUCTION` is not `1`; `HIBI_DEV_SERVER` can override it ([main.cjs](../electron/main.cjs#L7-L16)). The desktop launcher separately uses a loopback Vite URL ([start-desktop.mjs](../scripts/start-desktop.mjs#L1-L8)). The assistant is deterministic over `StudyData` and states “No network calls” ([TabyView.tsx](../src/ui/TabyView.tsx#L6-L21)). | Do not treat localhost as trusted. Production builds must use `loadFile`; keep AI/network adapters absent unless explicitly reviewed; if added, use an allowlist, authenticated local IPC or a narrowly bound endpoint, request-size/time limits, and redact prompts/responses from logs. |
| Credentials and secrets | High: API keys, session tokens, signing keys, or user data in source, environment, logs, or support exports could leak through the repository or shipped app. | No credential fields, secret reads, authentication flow, or remote client are established by the current source. The documented boundary says there is no account/authentication contract ([local capability contracts](./local-capability-contracts.md#non-contracts)). The support bundle is a local JSON export of study data ([SettingsView.tsx](../src/ui/SettingsView.tsx#L24-L30)). | Keep secrets out of source, seed data, fixtures, `localStorage`, telemetry, and support exports. Add secret scanning and packaged-artifact inspection to release CI. If credentials are later needed, use the OS credential store, least privilege, rotation, and explicit consent. Treat exported support JSON as sensitive. |
| External integrations | Medium: calendar, update, notification, analytics, or AI integrations could transmit personal planning data or create new trust boundaries. | Current settings identify external calendar sync as “Not configured,” Brain/hardware as unavailable offline, and updates as offline; the documented non-contracts exclude cloud persistence, external calendar APIs, remote notifications, and external AI ([SettingsView.tsx](../src/ui/SettingsView.tsx#L23-L27); [local capability contracts](./local-capability-contracts.md#non-contracts)). Native notifications receive a locally built payload through the narrow bridge, and the main-process scheduler sanitizes it before scheduling ([App.tsx](../src/App.tsx#L129-L171); [preload.cjs](../electron/preload.cjs#L3-L9); [notifications.cjs](../electron/notifications.cjs#L100-L111)). | Keep integrations disabled by default and make each future integration explicit, permissioned, auditable, and separately documented. Never infer “connected” from UI labels alone; test that no unexpected outbound requests occur in production builds. |
| Redistribution / provenance | High: extracted visual assets, Rive files, audio, fonts, icons, or proprietary code may be copyrighted, trademarked, or licensed for use only in the original product. | The asset README requires owner approval for every included asset before distribution ([asset policy](../public/companion-assets/README.md#L1-L11)). The design docs describe this as an isolated study replica, not a production product ([replica design](./hey-taby-replica-design.md#L1-L5)). | Do not publish installers, screenshots, or asset bundles until rights are recorded. Maintain an inventory with source, owner, license/permission, allowed channels, attribution, and removal contact; remove unapproved assets and avoid branding that implies endorsement. |

## Boundary observations

- Electron exposes only `info`, login-item settings, notification synchronization, and a notification test action through `contextBridge` ([preload.cjs](../electron/preload.cjs#L3-L9)). The notification IPC handler delegates entry validation to `sanitizeEntries` in the scheduler; the login-item handler coerces its boolean input with `Boolean(enabled)` ([main.cjs](../electron/main.cjs#L19-L34); [notifications.cjs](../electron/notifications.cjs#L100-L111)).
- Local data is stored under `localStorage` and there is no encrypted-store, account, or sync contract ([local capability contracts](./local-capability-contracts.md#persistence)). Anyone with access to the user profile or an exported support bundle may read planning data.
- Browser-served companion assets are referenced under `/companion-assets/...`; the registered runtime list is image/video only, while the quarantined Rive/audio files are not registered ([companion-assets.ts](../src/assets/companion-assets.ts#L3-L8), [companion-assets.ts](../src/assets/companion-assets.ts#L33-L42), [companion-assets.test.ts](../src/assets/__tests__/companion-assets.test.ts#L1-L12)).

## Release gates

Before redistributing a build:

1. Confirm asset and trademark permissions, including the Rive files, WASM, audio, icons, and extracted media.
2. Inspect the packaged file list for compiled bundles, native binaries, debug recordings, credentials, and unexpected assets.
3. Verify the production path uses a local packaged document, not a development or configurable localhost URL.
4. Run an outbound-network check and confirm no external AI, analytics, update, calendar, or hardware service is contacted.
5. Verify support exports contain no credentials and are clearly treated as sensitive personal data.
6. Run the renderer safety check, quarantine tests, and notification tests; review any changes to preload, Electron main-process handlers, asset registration, or package dependencies ([renderer-safety-check.mjs](../scripts/renderer-safety-check.mjs), [companion-assets.test.ts](../src/assets/__tests__/companion-assets.test.ts), [notifications.test.cjs](../electron/notifications.test.cjs), [package.json](../package.json#L7-L16)).

## Limitations

This review is based on the repository contents and source references above. It does not establish the absence of vulnerabilities in Electron, npm dependencies, the operating system, the build host, or any future packaging configuration. It also does not grant redistribution rights for extracted material.
